## 1. Master Requirements Ranking & Metric Evaluation Matrix

In the table below, the five core requirements (**Response Time**, **Reliability**, **Throughput**, **Battery/Power**, and **Security**) are ranked from **1 (Highest Priority)** to **5 (Lowest Priority)** for each of the six hospital computing environments, accompanied by target technical bounds.

| Computing Environment | Recommended OS Type | Rank 1 (Highest) | Rank 2 | Rank 3 | Rank 4 | Rank 5 (Lowest) | Patient-Safety Criticality |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Bedside Patient Monitors** | Hard Real-Time OS (RTOS) | **Response Time** ($\le 2\text{ ms}$ IRQ/alarm bound) | **Reliability** ($99.999\%$ uptime, watchdog recovery) | **Security** (Secure boot, signed firmware) | **Battery** (Emergency backup during power loss/transport) | **Throughput** ($\sim\text{KB/s}$ sensor telemetry streams) | **Critical (Direct Life Support):** Missed or delayed arrhythmia/apnea alarms cause immediate patient harm. |
| **2. Nurses' Handheld Tablets** | Mobile OS | **Battery** (12-hr shift endurance, DVFS, sleep states) | **Response Time** ($<16.6\text{ ms}$ frame render, fast push wake) | **Security** (FDE, sandboxing, biometric timeout) | **Reliability** (Stateless client; server holds state) | **Throughput** (Lightweight JSON/FHIR payloads) | **High (Point-of-Care):** Receives urgent distress alerts and verifies barcode medication administration (BCMA). |
| **3. Doctors' Desktop Workstations** | Interactive Desktop GPOS | **Response Time** (Low GUI latency, preemptive multitasking) | **Security** (RBAC, smartcard SSO, audit logs) | **Throughput** (Gigabit PACS image loading, GPU rendering) | **Reliability** (Session persistence, VDI recovery) | **Battery** (AC-powered stationary terminal) | **Moderate-High (Diagnostic):** UI freezes or display errors delay clinical orders and image interpretation. |
| **4. Central Patient Database Server** | Enterprise Server OS | **Reliability** (ACID durability, ECC RAM, HA clustering) | **Security** (PHI encryption, MAC, immutable logs) | **Throughput** (High IOPS/TPS for 500 beds + clients) | **Response Time** ($<50\text{ ms}$ query tail latency) | **Battery** (Data-center UPS & generator backed) | **Critical (Hospital-Wide):** Corruption or downtime halts allergy checks, prescriptions, and central alarm routing. |
| **5. MRI Imaging Server** | HPC / Batch & Stream Server OS | **Throughput** (Multi-GB/s DMA, SIMD/GPU FFT pipelines) | **Reliability** (Prevents corrupted scans & re-scans) | **Response Time** (Soft deadlines: seconds to minutes per volume) | **Security** (DICOM header PHI protection, VLAN isolation) | **Battery** (Dedicated facility high-wattage power) | **Moderate (Indirect Clinical):** Reconstruction failure forces repeat scans for sedated/critical patients. |
| **6. Partner-Hospital Network Connection** | Hardened Network Gateway / Firewall OS | **Security** (mTLS, DPI, IPS, Zero-Trust perimeter) | **Reliability** (Redundant BGP/WAN failover links) | **Throughput** (Line-rate AES-GCM crypto & DICOM transit) | **Response Time** (Low packet jitter for telemedicine) | **Battery** (Rack-mounted UPS power rails) | **High (System Integrity):** Breach enables ransomware lateral movement; link drop blocks trauma transfer records. |

## 3. Historical OS Paradigms, Complexity & "Single GPOS Everywhere" Comparison

| Environment | Historical OS Paradigm Lesson Applied | Core OS Operation & Time/Space Complexity | Impact of "One General-Purpose OS Everywhere" (vs. Specialized OS) |
| :--- | :--- | :--- | :--- |
| **1. Bedside Patient Monitors** | **Real-Time Embedded Systems:** Static resource reservation and priority preemption prevent unbounded delays. | **Fixed-Priority Preemptive Scheduler:**<br>Time: $\mathcal{O}(1)$ via bitmap `CLZ`<br>Space: $\mathcal{O}(1)$ static TCBs ($M$ fixed tasks) | **Worst-Case Alarm Latency:** Degrades from $\le 2\text{ ms}$ (RTOS) to $>50\text{--}500\text{ ms}$ (GPOS page faults/locks) — **Unsafe.**<br>**Memory:** Increases from $\sim 1\text{--}16\text{ MB}$ to $\ge 2\text{ GB}$ RAM.<br>**Admin:** Requires invasive `PREEMPT_RT` tuning & IEC 62304 re-certification. |
| **2. Nurses' Handheld Tablets** | **Mobile OS:** Aggressive sleep states, heterogeneous core scheduling, and app sandboxing preserve battery and privacy. | **Event Loop & Energy-Aware Scheduler:**<br>Time: $\mathcal{O}(\log P)$ task placement<br>Space: $\mathcal{O}(P)$ active sandboxed apps | **Worst-Case Alarm Latency:** Push alerts delayed if desktop GPOS lacks mobile wake-lock hardware integration.<br>**Memory:** Desktop GPOS bloats RAM ($4\text{--}8\text{ GB}$), increasing DRAM standby drain.<br>**Admin:** High effort to strip desktop UI into touch-friendly, power-efficient kiosk mode. |
| **3. Doctors' Desktop Workstations** | **Time-Sharing & Personal OS:** Preemptive time-slicing and rich windowing systems maximize interactive clinician productivity. | **Fair Time-Sharing Scheduler (CFS/EEVDF):**<br>Time: $\mathcal{O}(\log P)$ tree update<br>Space: $\mathcal{O}(P)$ dynamic processes | **Worst-Case Alarm Latency:** Native fit ($<50\text{ ms}$ interactive response).<br>**Memory:** Native fit ($16\text{--}32\text{ GB}$ RAM for EHR + PACS).<br>**Admin:** Low effort; standard enterprise desktop group-policy/MDM tooling applies directly. |
| **4. Central Patient Database Server** | **Time-Sharing & Multiprogrammed Server OS:** High-concurrency I/O multiplexing and virtual memory isolation prevent single-client stalls. | **$B^+$-Tree Indexing & Hash Telemetry Lookup:**<br>Time: $\mathcal{O}(\log_b R)$ query; $\mathcal{O}(1)$ bed update<br>Space: $\mathcal{O}(R + N)$ buffer pool | **Worst-Case Alarm Latency:** Acceptable soft real-time ($<50\text{ ms}$) if desktop GUI daemons are disabled.<br>**Memory:** Native fit ($128\text{--}512\text{ GB}$ ECC RAM).<br>**Admin:** Low effort if using server profile of GPOS; desktop bloatware must be stripped. |
| **5. MRI Imaging Server** | **Batch OS:** Non-interactive job queuing and DMA offload maximize utilization of scarce, high-cost compute accelerators. | **3D FFT Volumetric Reconstruction ($V = D^3$):**<br>Time: $\mathcal{O}(D^3 \log D) = \mathcal{O}(V \log V)$<br>Space: $\mathcal{O}(D^3) = \mathcal{O}(V)$ voxel buffers | **Worst-Case Alarm Latency:** N/A (Batch workload; scanner hardware handles RF safety).<br>**Memory:** Native fit ($256\text{ GB+}$ RAM + GPU VRAM) using huge pages.<br>**Admin:** Moderate effort; requires GPU compute drivers and NUMA pinning on standard GPOS. |
| **6. Partner-Hospital Network Connection** | **Network / Bastion OS:** Minimal attack surface, kernel-bypass packet processing, and strict privilege separation. | **Stateful Packet Filter / eBPF Hash Lookup:**<br>Time: $\mathcal{O}(1)$ flow lookup; $\mathcal{O}(F)$ linear ACL<br>Space: $\mathcal{O}(C + F)$ state table | **Worst-Case Alarm Latency:** Higher packet jitter than dedicated kernel-bypass appliance OS.<br>**Memory:** Over-provisioned ($4\text{--}8\text{ GB}$ vs. $\le 1\text{ GB}$ appliance OS).<br>**Admin:** Increased patching burden due to larger attack surface of unnecessary GPOS packages. |
